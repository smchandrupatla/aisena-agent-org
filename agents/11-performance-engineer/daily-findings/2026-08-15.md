# Daily Finding — 2026-08-15

**Agent:** 11-performance-engineer
**Date:** 2026-08-15

---

FINDING: Kafka 4.0+ changed the producer default `linger.ms` from 0 ms to 5 ms, which adds up to 5 ms latency under low load but reduces spiky tail latency at high throughput — AISENA's `aisena-stage0-events` topic should be tuned explicitly.

WHY_IT_MATTERS: AISENA's ingestion pipeline (produce.py → Kafka → consume.py) runs on the `aisena-stage0-events` topic. At Stage 0 load volumes are low, meaning the new 5 ms default will silently add worst-case 5 ms to every message at the producer without any batching benefit. As load scales in later stages, the default becomes advantageous — but the current default creates a hidden latency floor that should be an explicit, documented decision rather than an accidental one.

EVIDENCE:
- Jack Vanlightly, "Apache Kafka performance #1 - linger.ms", published 2026-07-07
  https://jack-vanlightly.com/blog/2026/7/7/apache-kafka-performance-1-lingerms
- Apache Kafka 4.3 Producer Configuration docs (official):
  https://kafka.apache.org/43/configuration/producer-configs/

RECOMMENDED_ACTION: In services/ingestion/produce.py (and any future producer configs), add an explicit `linger_ms` parameter with a comment documenting the trade-off. Set `linger_ms=0` for low-volume / latency-sensitive Stage 0 and Stage 1 workloads; raise to 5–20 ms only when sustained throughput justifies it. Add this as a tuning note to the performance baseline document.
